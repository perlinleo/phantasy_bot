# «Крутые тёлки» и «Камеди: Воля и Харламов»

Оба плагина работают локально, на CPU. Генератор изображений использовался только при
подготовке художественных ресурсов; пользовательские задачи не обращаются к нему.

| Плагин | Ввод | Настройки | Результат |
|---|---|---|---|
| `glamour_letters` | До 12 букв/знаков, до двух строк | Золотой салон, бриллиантовая ночь, красная дорожка | PNG 1600×1000 |
| `comedy_stage` | До 100 символов, до трёх строк по метрикам шрифта | Красная сцена 6/8 с, неоновый roast 6 с | MP4 1280×720, 24 fps, без звука |

Поддерживаются русский алфавит с Ё/ё, латиница, цифры и обычная пунктуация. Пробелы
и явные переводы строк сохраняются. Пробельный ввод, emoji и неизвестные глифы
отклоняются до очереди. Если фраза не помещается при читаемом размере, бот просит её
сократить; исходная строка не обрезается. Надпись на сцене не представляется цитатой ведущих.

## Установка ресурсов

Ресурсы не входят в Git и Docker image. Подготовленный пакет содержит `glamour.png`
и `comedy.png`; точные размеры и SHA-256 находятся в
[characters-v1.json](../src/media_bot/assets/characters-v1.json).
Поместите оба файла в `output/plugin-assets/v1/` на машине запуска. Передавайте отдельно
архив `output/characters-v1.tar.gz`, созданный при поставке; не используйте случайные
картинки с теми же именами. Путь должен оставаться неизменным во время активных задач.

В локальном `.env` укажите абсолютный путь и добавьте нужные ID к существующему списку:

```dotenv
PLUGIN_ASSETS_DIR=/absolute/path/to/phantasy_bot/output/plugin-assets/v1
ENABLED_PLUGINS=text_card,glamour_letters,comedy_stage
```

Проверка перед запуском:

```sh
uv run media-bot plugins validate
```

Если ресурс отсутствует, повреждён или не совпадает с закреплённой версией, команда
завершится ошибкой. Выключенные плагины не требуют пакета.

Для Docker используйте подготовленное read-only подключение:

```sh
docker compose -f compose.yaml -f compose.characters.yaml up --build
```

Overlay задаёт контейнерный `PLUGIN_ASSETS_DIR=/opt/phantasy/characters-v1`, отдельно
от локального абсолютного пути. У bot и worker один пакет; миграции его не используют.
Проверьте права чтения для UID 10001. Базовый compose.yaml не требует этого overlay.

## Офлайн-рендер без Telegram

Тот же JSON runner, что используется worker, можно вызвать напрямую. Например,
создайте `output/preview-input.json` (это локальный файл, не для Git):

```json
{
  "job_id": "preview",
  "lease_token": "preview-attempt",
  "plugin_id": "glamour_letters",
  "plugin_version": "1",
  "input_json": "{\"text\":\"ВАУ\"}",
  "options_json": "{\"preset\":\"gold_lounge\"}",
  "workspace": "output/preview"
}
```

```sh
uv run media-bot run-payload --input output/preview-input.json \
  --output output/preview-result.json --plugins glamour_letters \
  --assets-root output/plugin-assets/v1
```

Для видео используйте `plugin_id=comedy_stage`, `--plugins comedy_stage` и
`options_json` со значением `{"preset":"classic_red","duration_seconds":6}`.
В production worker передаёт абсолютные пути; для запуска из другой cwd они нужны
также в preview JSON и аргументах команды. Результат содержит относительное имя PNG/MP4.

## Проверки и ограничения

`make check` включает проверки Unicode/переполнения, SHA-256 и границ ресурсов,
пресетов/ревизий/доступа, SQLite persistence, настоящий MP4/ffprobe и завершение FFmpeg
при ошибке генератора кадров. CI использует синтетический атлас: эти тесты проверяют
композитинг и медиаконтракт, но не заменяют визуальную оценку реальных персонажей.

PNG ограничен 10 MiB, MP4 — 20 MiB; при превышении задача завершится ошибкой.
Используется общий JOB_TIMEOUT_SECONDS (300 секунд по умолчанию). В память не загружается
весь ролик: сохраняются несколько слоёв и текущий кадр, а не массив кадров на 6/8 секунд.

В v1 четыре модели повторяются на длинных строках; стили меняют окружение и материал
букв. Ведущие анимированы переключением и интерполяцией двух поз, без озвучки.
Подробности: [решение об artwork](decisions/0004-character-plugin-assets.md).
Пакет создан встроенным imagegen; исходные промпты поставляются рядом с пакетом.

Live-приёмка остаётся отдельной: оба инструмента и все пресеты в личном чате,
читаемость на Desktop/мобильном клиенте, progress, отмена, restart, resend, revoke и
реальные ошибки доставки. Успешный офлайн-рендер не означает пройденную Telegram-приёмку.
